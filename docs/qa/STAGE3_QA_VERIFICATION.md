## 3. Рекомендації для розробників на Етапах 4 та 5 (Реалізація коду)

1. **Room Entities та анотації (Етап 5):**
   - У `ShoppingItemEntity` використовувати точну конструкцію:
     ```kotlin
     @Entity(
         tableName = "shopping_items",
         foreignKeys = [
             ForeignKey(
                 entity = ShoppingListEntity::class,
                 parentColumns = ["id"],
                 childColumns = ["list_id"],
                 onDelete = ForeignKey.CASCADE
             ),
             ForeignKey(
                 entity = CategoryEntity::class,
                 parentColumns = ["id"],
                 childColumns = ["category_id"],
                 onDelete = ForeignKey.SET_NULL
             )
         ],
         indices = [Index("list_id"), Index("category_id")]
     )
     ```
2. **Транзакційність пакетного додавання (Multi-line Paste):**
   - У `ShoppingItemDao` обов'язково створити метод:
     ```kotlin
     @Insert(onConflict = OnConflictStrategy.REPLACE)
     suspend fun insertAll(items: List<ShoppingItemEntity>)
     ```
   - Забезпечити виклик у межах `@Transaction`, щоб додавання десятків товарів із буфера відбувалося за один атомарний запис на диск без блокування UI.
3. **Логіка оновлення `recent_items` (Часті товари):**
   - Для запобігання конфліктам унікального індексу `name` використати SQL `UPSERT`:
     ```sql
     INSERT INTO recent_items (name, category_id, last_used_at, use_count)
     VALUES (:name, :categoryId, :now, 1)
     ON CONFLICT(name) DO UPDATE SET
         use_count = use_count + 1,
         last_used_at = :now,
         category_id = coalesce(:categoryId, category_id)
     ```
4. **Android Маніфест (Етап 4):**
   - Переконатися, що файл `app/src/main/AndroidManifest.xml` взагалі не містить тегів `<uses-permission>` для версії MVP.
