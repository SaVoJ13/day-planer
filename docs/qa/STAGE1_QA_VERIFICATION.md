- ❌ Геолокаційні нагадування.

### 2.3. Коректність моделі даних та граматичних правил (Plurals)

1. **Правила плюралізації числівників (Plurals):**
   - У Розділі 3 PRD для кожної з 4 мов наведено точні граматичні форми:
     - `uk` (слов'янська група: 1, 2–4, 5+): `one` («1 товар»), `few` («2 товари»), `many` («5 товарів»).
     - `pl` (польська група: 1, 2–4, 5+): `one` («1 element»), `few` («2 elementy»), `many` («5 elementów»).
     - `en` (германська група: 1, >1): `one` («1 item»), `other` («2 items»).
     - `ru` (слов'янська група: 1, 2–4, 5+): `one` («1 товар»), `few` («2 товара»), `many` («5 товаров»).
   - Відповідає правилам CLDR та формату `plurals.xml` в Android SDK.

2. **Модель даних (Entity Schema):**
   - Сутності `ShoppingList`, `Category`, `ShoppingItem`, `RecentItem` спроєктовані з урахуванням реляційної цілісності:
     - Наявні первинні ключі (`PK`), зовнішні ключі (`FK`) з каскадним видаленням (`on-delete CASCADE` для елементів списку).
     - Локалізовані категорії використовують ключ `nameKey` для підтягування рядків із ресурсів, що унеможливлює проблеми при перемиканні мови інтерфейсу.
     - Відокремлена таблиця `RecentItem` запобігає засміченню списків та оптимізує автодоповнення.

## 3. Застереження та інженерні рекомендації для Етапу 2 (UX та локалізація) і Етапу 3 (Архітектура)

1. **UX мультирядкового вставлення (Ф-5):**
   - Користувачі часто копіюють списки з месенджерів із маркерами списку (`- `, `• `, `* `, `1. `). Необхідно закласти автоматичне очищення цих префіксів (sanitization) під час парсингу рядків.
2. **Розміри текстових контейнерів у Compose при локалізації:**
   - Українські та польські рядки інтерфейсу в середньому на 15–30% довші за англійські (наприклад, «Add all» vs «Додати всі», «Settings» vs «Налаштування»). Усі кнопки, діалоги та чіпи повинні підтримувати динамічне перенесення або мати достатній padding без еліпсису (`...`).
3. **Регістронезалежність для частих покупок (`RecentItem`):**
   - На рівні Room SQLite для поля `name` у `RecentItem` рекомендується застосувати `COLLATE NOCASE` або нормалізацію (lowercase при порівнянні), щоб «Молоко» та «молоко» не створювали подвійних записів в історії.
4. **Empty States та Onboarding:**
   - Для першого запуску застосунку передбачити дружній Empty State на головному екрані з кнопкою «Створити перший список» або готовим демо-шаблоном «Щотижневі покупки».
