# DEFINITION OF DONE (Критерії готовності)

> Діє для проєкту «Список покупок» згідно з Конституцією команди агентів (версія 2.0).
> Жодне завдання чи етап не може вважатися завершеним без виконання відповідних критеріїв і надання фактичних доказів. Порушення є Червоною лінією №1.

---

## 1. Рівні готовності

### 1.1. Рівень завдання (Task Level)
Завдання переходить у статус `Done` виключно за виконання:
1. **Картка завдання:** Створена в `docs/tasks/TASK-<ID>.md`, заповнена, журнал оновлений (що зроблено, стан, наступний крок, пастки).
2. **Код і структура:**
   - Код відповідає архітектурним стандартам і не містить хардкоду рядків (усі тексти — в `strings.xml` для 4 мов).
   - Немає закоментованого або мертвого коду, відсутні тимчасові заглушки без позначки TODO.
3. **Сторонні бібліотеки:**
   - Якщо додано нову залежність, її ліцензія перевірена за першоджерелом і внесена у `docs/THIRD_PARTY.md`.
4. **Автоматичні перевірки:**
   - Проходять модульні тести (`testDebugUnitTest`).
   - Відсутні помилки лінтера (`lintDebug`).
   - Проєкт успішно збирається (`assembleDebug`).
5. **Незалежна перевірка (п. 2.1 Конституції):**
   - Автор змін **не ставить** `QA Verified`.
   - Отримано верифікацію від незалежного QA-субагента (або Власника) з наданням реального виводу перевірок.
6. **Git:**
   - Зміни закомічені у відповідну гілку із зрозумілим повідомленням за стандартом Conventional Commits.
   - Злиття в `main` відбувається лише після `QA Verified` і проходження перевірок.

---

### 1.2. Рівень етапу (Phase Gate Level)
Перехід між етапами (Етапи 0–7) вимагає проходження воріт `Owner Approved`:
1. Підготовлено підсумковий звіт етапу у `docs/reports/` та сформульовано у чаті українською мовою.
2. Усі обов'язкові артефакти етапу створені та узгоджені.
3. Оновлено `CURRENT_STATE.md`, `TASK_BOARD.md` та `SESSION_LOG.md`.
4. Усі відкриті питання, що потребують рішення Власника, зафіксовані в `docs/governance/OWNER_INBOX.md` з чіткими варіантами й рекомендаціями.
5. Отримано явне схвалення Власника (`Owner Approved`). Мовчання не вважається схваленням.

---

## 2. Спеціальні критерії для компонентів MVP

### 2.1. Локалізація (4 мови: uk, ru, pl, en)
- Усі системні повідомлення, кнопки, діалоги, порожні стани, помилки та налаштування перекладені для кожної з 4 мов.
- Перевірено форми множини (Plurals) для числівників (наприклад, 1 товар, 2 товари, 5 товарів).
- Жодного автоматичного перекладу введених користувачем назв товарів.
- Відсутнє обрізання тексту в UI при довгих перекладах.

### 2.2. Приватність і безпека
- У маніфесті відсутній дозвіл `android.permission.INTERNET` (Zero Network MVP).
- Жодних секретів, ключів, токенів чи персональних даних у коді та git-історії (Червона лінія №3).
- Жодних SDK сторонніх рекламних чи аналітичних мереж без рішення Власника.
- Усі дані зберігаються суто локально на пристрої користувача в Room SQLite.

### 2.3. Офлайн-робота та надійність
- Застосунок працює повністю автономно без інтернет-з'єднання.
- Дані не втрачаються при перезапуску програми, зміні орієнтації екрана чи аварійному закритті.
