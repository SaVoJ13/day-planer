# PRD: Android-застосунок «Список покупок» (Product Requirements Document)

> Версія: 1.0 · Дата: 2026-11-20 · Роль: Дослідник продукту / Керівник проєкту · Статус: Затверджено

---

## 1. Візія та цілі продукту
Створити найшвидший, простий та ненав'язливий офлайн-інструмент для складання та ведення списків покупок на Android.

**Основний користувацький цикл:**
> Створити список → Швидко додати товари (вручну або вставленням тексту) → Відмічати куплене в магазині без переривань на рекламу → Повторно використати список наступного разу.

---

## 2. Цільова аудиторія та сценарії
- **Люди, які регулярно роблять щотижневі закупівлі:** Потребують збереженого списку продуктів, який можна скинути («зняти всі прапорці») та використати знову.
- **Користувачі месенджерів:** Отримують список продуктів від рідних у Viber/Telegram/WhatsApp та хочуть вставити весь текст одним кліком замість передруковування кожного пункту.
- **Цінителі приватності та швидкодії:** Не хочуть реєструватися, пам'ятати паролі чи чекати підключення до сервера в підвальних приміщеннях супермаркетів.

---

## 3. Мовна стратегія (4 мови)
Інтерфейс першого релізу повністю підтримує 4 мови:
1. **Українська (`uk`)** — основна мова.
2. **Англійська (`en`)** — міжнародна.
3. **Польська (`pl`)** — для ринку Польщі та діаспори.
4. **Російська (`ru`)** — для користувачів відповідного мовного середовища.

### Вимоги до локалізації:
- Автоматичне підхоплення системної мови пристрою.
- Можливість ручного вибору мови в налаштуваннях із миттєвим перемиканням без перезапуску застосунку.
- Збереження вибраної мови в локальних налаштуваннях (`DataStore` або `SharedPreferences`).
- Усі системні тексти, повідомлення про помилки, діалоги, назви категорій та одиниць виміру мають переклади.
- Підтримка граматичних форм множини (Plurals) для числівників у кожній мові:
  - *Українська:* 1 товар, 2–4 товари, 5 товарів.
  - *Польська:* 1 element, 2–4 elementy, 5 elementów.
  - *Англійська:* 1 item, 2+ items.
  - *Російська:* 1 товар, 2–4 товара, 5 товаров.
- **Сувора заборона:** Назви товарів, введені користувачем, ніколи не перекладаються автоматично.

## 4. Специфікація функціональності MVP

### Ф-1. Керування списками покупок
- Створення нового списку із зазначенням назви та вибором колірного маркера чи іконки.
- Перейменування списку.
- Видалення списку з діалогом підтвердження.
- Відображення прогресу списку: кількість куплених / загальна кількість товарів (наприклад, `5 / 12`).
- Дія «Повторити список» / «Скинути відмітки»: одним натисканням зняти всі позначки з куплених товарів, повертаючи їх в активний стан.

### Ф-2. Керування товарами
- Додавання товару з назвою.
- Необов'язкова кількість (число: 1, 2, 0.5 тощо).
- Необов'язкова одиниця виміру (шт, кг, г, л, уп / pcs, kg, g, l, pack тощо).
- Призначення категорії (із попередньо визначеного набору або «Без категорії»).
- Редагування назви, кількості та категорії товару.
- Видалення товару.

### Ф-3. Базові категорії продуктів
Попередньо встановлені 8 зручних категорій із візуальними іконками:
1. 🥦 Овочі та фрукти (Vegetables & Fruits)
2. 🥛 Молочні продукти (Dairy)
3. 🥩 М'ясо та риба (Meat & Fish)
4. 🍞 Хліб та випічка (Bakery)
5. 🌾 Бакалія та крупи (Grocery & Grains)
6. 🧃 Напої (Beverages)
7. 🧼 Побутова хімія та дім (Household & Cleaning)
8. 📦 Інше (Other)

### Ф-4. Відмічання та робота в магазині (In-Store Mode)
- Натискання на чекбокс або назву переводить товар у статус «Куплено».
- Куплені товари перекреслюються і переміщуються у згортаєму нижню секцію «Куплені товари» (`Completed`).
- Можливість повернути куплений товар назад в активні одним дотиком.
- Кнопка швидкої дії в меню списку:
  - «Очистити куплені» (видалити лише куплені товари).
  - «Скинути всі» (зробити всі товари знову некупленими для наступного походу).

### Ф-5. Швидке додавання та мультирядкове вставлення (Multi-line Paste)
- **Inline Quick Add:** Текстове поле швидкого вводу внизу екрана деталей списку: ввів назву → натиснув Enter або кнопку `+` → товар миттєво додано, поле очищено для наступного.
- **Розумне вставлення кількох товарів:** Якщо користувач вставляє з буфера обміну текст, що містить кілька рядків (розділених `\n`) або елементи, розділені комами (`,`), з'являється діалог швидкого розбиття:
  - Користувач бачить список розпізнаних позицій.
  - Може зняти галочки з непотрібних.
  - Натискає «Додати всі (X)» → всі позиції створюються за один крок!

### Ф-6. Історія товарів та автопідказки (Часті товари)
- Усі додані коли-небудь назви товарів зберігаються в локальній таблиці історії.
- Під час введення назви у полі швидкого додавання показуються 3–5 найбільш релевантних частих товарів для додавання в один дотик.

### Ф-7. Повна офлайн-робота (Zero Network MVP)
- Локальна база даних Room SQLite.
- Відсутність дозволу `android.permission.INTERNET` у маніфесті для MVP.
- Жодних акаунтів, авторизацій чи синхронізацій із зовнішніми серверами.
- Миттєвий холодний старт застосунку.

### Ф-8. Налаштування інтерфейсу
- Вибір теми оформлення: Світла, Темна, Системна (Material You / Dynamic Colors за наявності Android 12+).
- Ручний вибір мови (Українська, English, Polski, Русский) з негайним застосуванням.
- Інформація «Про додаток» та версія.

## 5. Монетизація та дизайн рекламних місць
- **Цільова модель:** Безкоштовний застосунок із банерною рекламою.
- **Стратегічне обмеження для утримання користувачів:**
  - **ЖОДНОЇ реклами на екрані активних покупок (List Details).** Людина в магазині має максимальний комфорт і швидкість.
  - Розміщення реклами: один статичний адаптивний банер у нижній частині головного екрана (список усіх списків).
  - Жодних блокуючих попапів, повноекранних інтерстишелів чи відео при відкритті списку чи викреслюванні товару.
- **Статус у MVP:** Дозвіл на Інтернет та сам рекламний SDK буде підключено на етапі релізної підготовки після окремого узгодження з Власником; на етапі початкової збірки MVP макет містить плейсхолдер або вимкнений стан.

---

## 6. Межі та явні не-цілі (Non-Goals) для першого релізу
- ❌ Хмарна синхронізація між пристроями.
- ❌ Реєстрація користувачів та профілі.
- ❌ Сканування штрихкодів та розпізнавання камерою.
- ❌ Інтеграція з цінами та каталогами конкретних мереж супермаркетів.
- ❌ Підрахунок суми чека, бюджет чи фінансовий облік.
- ❌ Рецепти та меню-планування.
- ❌ Геолокаційні нагадування про магазини поруч.

## 7. Модель даних (High-Level Entity Schema)

```
ShoppingList
├── id: Long (PK, auto-generated)
├── name: String
├── colorHex: String
├── createdAt: Long (timestamp)
├── isArchived: Boolean
└── orderIndex: Int

Category
├── id: Long (PK)
├── nameKey: String (resource identifier for localization)
├── iconName: String
└── colorHex: String

ShoppingItem
├── id: Long (PK, auto-generated)
├── listId: Long (FK -> ShoppingList.id, on-delete CASCADE)
├── name: String
├── quantity: Double?
├── unit: String? (e.g., "kg", "pcs")
├── categoryId: Long? (FK -> Category.id)
├── isCompleted: Boolean
├── createdAt: Long
└── orderIndex: Int

RecentItem
├── id: Long (PK, auto-generated)
├── name: String (Unique)
├── categoryId: Long?
├── lastUsedAt: Long
└── useCount: Int
```

## 8. Критерії приймання для QA
1. **Користувацькі сценарії:**
   - Можна створити список, додати 5 товарів, викреслити 2, скинути список (всі 5 знову активні) — перевірено без збоїв.
   - Вставлення тексту з 4 рядків розбиває його на 4 окремі товари.
2. **Локалізація:**
   - Перемикання на кожну з 4 мов коректно перекладає всі елементи навігації, назви категорій, одиниці виміру та форми числівників.
3. **Офлайн та збереження:**
   - Після примусового закриття застосунку всі списки та товари залишаються незмінними.
